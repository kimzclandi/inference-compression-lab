## 领域地图与本单元位置

推理优化解决的是：在可接受质量下减少计算、数据搬运、内存和用户等待。对象依次是权重 W、激活 h、Attention 的 KV、请求序列和硬件执行路径。

本单元位置为“固定模型/数据 → 权重量化 → logits 扰动 → greedy 输出 → 任务质量 → 运行成本”。缓存处理重复计算，分桶处理 padding；它们不能替代量化误差分析。学校机器人部署是另一条待接入的硬件证据线。

- 必须掌握：weight-only 与激活/KV 量化的区别；logits/argmax；自回归；同输入干预；质量/文件/RSS/TTFT/decode 的定义；选择偏差。
- 进阶：模块间误差交互、激活分布、逐算子回退、量化校准、置信区间、kernel 的带宽/计算约束。
- 暂可忽略：本轮没有实现的稀疏、token 压缩、分布式训练、手机专用 kernel。不要为了匹配 JD 先堆术语。

## 输入、输出、形状与执行顺序

输入是一段 passage 和 question，经同一个 chat template/tokenizer 得到 token IDs `[B,S]`。本轮 B=1；示例 S=110。

Qwen2.5-0.5B 的 hidden size H=896，24 个 decoder block，词表 V=151936。Embedding 将 IDs 映射为 `[1,S,896]`；每个 block 的 Attention/MLP 和 residual 更新隐藏状态；末端投影得到 `[1,S,151936]`。取最后位置 `logits[0,-1,:]`，greedy 选最大值对应的 token。KV 保存历史 K/V，下一步只输入 `[1,1]`。权重 Q4/Q8 不意味着这些 KV 变成整数。

group_size=64 的 affine weight-only 量化可理解为每组用 scale 和偏移把浮点权重映射到有限整数级别。形式为 `q=clip(round((w-b)/s))`，重构为 `w_hat=s*q+b`；w 是原权重，q 是整数码，s 是组内尺度，b 是偏移。此式说明近似，不等于逐行复述 MLX 的端点选择和打包实现。实际执行调用 MLX 的量化层/Metal kernel。[官方 API](https://ml-explore.github.io/mlx/build/html/python/nn/_autosummary/mlx.nn.QuantizedLinear.html)

把 Q4 权重反量化成 FP16 只得到 `w_hat`，已经丢掉的精度不会恢复。本轮从原 FP16 checkpoint 复制一个 block 的原始张量；其余张量必须与 Q4 完全相同。保存后重新加载，核对 7 个 projection 的实际类型、dtype、bits/group_size 和输出，才证明干预生效。

## 五个核心思维模型

|模型|是什么、为什么成立|适用问题|失效边界|面试与工作怎么用|
|---|---|---|---|---|
|排名阈值|greedy 输出由谁最大决定，不由整体误差均值决定。原 top1 与其余最大值的差越小，越容易被差分扰动翻转|首 token 异常、不同精度 token 不同|只看原 top2 会漏掉第三个 token 超车；margin 不是校准过的正确率|先对齐同 prompt，比较全词表赢家、参考 token 排名及 margin|
|自回归因果链|首 token 改变后，下一步的条件输入已不同，后续偏差可能被放大|区分起因与后续分叉|首 token 一致也不保证后续相同；多次采样还要控制随机性|先分析共同输入下首次分歧；后续需要 teacher forcing 才能比较同条件 logits|
|受控干预|只改一个 block，其余保持一致，并匹配成本，观察变化才有归因基础|选模块、检查回退是否真的有效|一次单 block 干预不能识别交互或唯一根因；24 次筛选有选择偏差|展示张量来源检查、对照规则和负结果，不只展示最好数字|
|多目标取舍|质量、文件、运行内存、TTFT、decode 是不同目标，通常互相牵制|选择 Q8 或混合精度，评估落地成本|不同硬件/任务可能改变排序；18/74 相同不代表错误样本相同|做同轮比较，不把压缩率当内存降幅，不声称一个指标赢就全面更好|
|证据分层|协议、原始记录、重算、复跑、独立确认分别回答不同问题|判断结论能支持到哪里|校验和只防意外更改，不证明数据真实；重复 dev 不是盲测|提前写失败也接受的规则，保存失败，明确哪些是新执行/旧重算/尚未验证|

一个可迁移的边界：设原 logits 为 z，赢家 a，`m=z_a-max(z_j,j≠a)>0`。量化扰动为 δ，若每个 token 都满足 `|δ_j|<m/2`，则赢家一定保持；这是充分条件，不是必要条件。所有 logits 加同一个大常数可以完全不改排名。符号 j 是词表 token 索引，m 是原最大间隔，δ 是同输入下精度改变引起的数值变化。

## 三个核心取舍

1. **整体 Q8，还是 Q4 加局部 FP16？** Q8 方案简单、稳定性较好；混合方案可能以较小权重增加恢复少数错误。本轮两者 EM 都是 18/74，但 Q8 F1 为 29.68%、首 token 翻转 3 题；混合 F1 为 28.88%、翻转 35 题。局部回退更小、更快的证据仅限当前负载；模块筛选还付出了探索成本。实践中先满足任务质量门槛，再判断资源约束；没有通用赢家。
2. **追求 FP16 一致性，还是任务正确率？** 一致性适合检查实现和误差传播；任务正确率才回答用户有没有得到正确答案。FP16 本身只对 19/74，Q4 还新增过 3 个 FP16 答错的正确样本。不能把 FP16 输出当真值，也不能以“有时更对”免除回归验证。两套指标应并列。
3. **先广泛选层，还是先留确认数据？** 少量失败样本适合快速生成假设；但在同一 dev 上选 24 次再报告最好方案容易乐观。本轮用预定规则和等成本对照约束探索，但并未消除选择偏差。工程上固定方案后再看新的、任务匹配的数据；确认失败也保存，不能反复看确认集后调参再称确认。

共识是同输入、同基线和不泄漏确认结果；尚未解决的是 block 10 在其他任务/长度上是否有效，以及同成本的其他组合是否更优。本轮不替这些问题给确定答案。

## 30 秒面试回答

> 我从 Qwen Q4 的真实回归样本出发，先复现 FP16/Q4/Q8，再检查同 prompt 的首 token logits 和排名。固定 6 个退化样本，对 24 个 block 逐一恢复原始 FP16 权重，按预注册规则选择 block 10，并以等成本 block 22 作对照。74 题 dev 的 EM 从 16 到 18，对照仍为 16；代价是增加约 21 MB 权重和约 1.9% 的 decode 速度下降。这是重复 dev 上的探索结果，我没有把它说成通用敏感层或新算法。

深入追问：为何不是 dequantize？为什么原 top2 顺序未变仍可能换 token？为何用 +12 对照、还缺什么对照？为什么五轮轮换和新进程？为什么 Q8 和混合都 18/74 还不能说质量相同？为什么不把六个筛选样本的恢复当独立验证？

常见错误回答：“Q4 变成 FP16 就恢复精度”“EM 涨了所以算法有效”“first token 一样所以质量无损”“模型小了所以功耗同比下降”“第 10 层就是 Attention outlier 的根因”“Mac 快就能在华为手机快”。这些都省略了必要条件或越过当前证据。
