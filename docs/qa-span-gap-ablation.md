# Selected-window margin-gap ablation / 选中窗口 margin-gap 消融

**结果：实现确实不同，但本次真实训练/校准数据没有产生特征差异，未观察到质量提升。** 四个固定拟合全部收敛；FP32两种方法均无合格校准阈值，INT8两种方法均选择0.7，所有校准得分和决定完全相同。不得由此宣称两种机制普遍等价。

**Result: the mechanisms differ, but this development cohort produces identical feature inputs.** All four fixed fits converged. Both FP32 arms failed calibration; both INT8 arms selected 0.7 with identical scores and decisions. This is an uninformative quality comparison for cross-window competition, not evidence of general equivalence or improvement.

本实验为AI辅助实现与复跑。默认运行时、历史实验和发布流程未更改。预先固定的实现/协议提交为 `59972c44e53b708b97c149de1981eaa5dbbc830c`，所有真实拟合在该提交之后执行。

## Mechanism / 第三特征是什么

固定解码器先为每个窗口找合法span，再按“该span的start+end分数减去本窗口CLS的start+end分数”选出全局答案。把这个差记作margin。这里的第三特征度量：选中答案相对于最强的**不同规范化答案**领先多少。

设选中答案为 `a*`，其窗口为 `w*`，margin为 `m*`；`S`是所有窗口的合法span集合，`S_w*`是选中窗口的合法span集合，`N(a)`是答案规范化函数（使用固定EM规则）。则：

- 原第三特征：`g_all = m* - max{m(s) : s∈S, N(s)≠N(a*)}`。
- 新第三特征：`g_local = m* - max{m(s) : s∈S_w*, N(s)≠N(a*)}`。

`m(s)`始终使用span所在窗口自己的null分数。两个候选集都非空时，局部集合是全局集合的子集，因此 `g_local ≥ g_all`。相等的充分条件是全局最佳不同答案已经位于选中窗口；单窗口时必然相等。若选中窗口不存在不同答案，局部gap未定义，必须失败，不能填0、丢样本或退回其它窗口。

本消融保持原始选中答案不变，只改变第三特征的竞争答案集合。差异传递路径是“竞争集合改变 → 第三特征改变 → 重拟合后的排序分数与拒答决定可能改变 → 指标可能改变”。如果特征及其余输入完全相同，固定下游得到相同指标是预期结果，并不是第二份独立的无损证据。

它衡量分数竞争，并不是正确率。gap增大可能仅仅是看不到另一个窗口的强竞争答案。重新拟合后，标准化、系数和阈值选择也可能变化，因此不能从gap增大推出分数或精度一定提高。

## Two-window counterexample / 两窗反例

下面是合法的合成解码记录，不是模型实测，也不参与训练或校准。用false-mask分隔token，使答案不能跨分隔位置拼接，避免复合span掩盖关键机制。

| 窗口 | 合法答案 | margin | 如何处理 |
|---|---|---:|---|
| 0（选中窗口） | Alpha | 10 | 全局选中答案 |
| 0 | Beta | 2 | 本窗不同答案 |
| 1 | Alpha | 9.5 | 规范化后与选中答案相同，排除 |
| 1 | Gamma | 9 | 全局最强的不同答案 |

所以 `g_all=10−9=1`，`g_local=10−2=8`。这也解释了为什么不能只检查每窗winner：窗口1的winner是重复Alpha，但该窗口第二个候选Gamma才是需要保留的竞争答案。

## Change isolation / 实际改了什么

实现先对全部窗口执行原校验和解码；只将选中窗口送入同一合法span枚举逻辑计算新的第三特征，再替换五维向量的索引2。第1、2、4、5项、答案选择和标签不变。特别是第五项仍为原始全部窗口数的`log1p`，不能误改成单窗口计数。

这是一条离线消融路径，没有替换 `lab/qa_risk_calibration.py` 或生产/原型入口。为保留校验，该路径会重复计算部分特征；未测量性能，也不声称提速。

## Fixed experiment / 固定实验与数值边界

[协议](../configs/qa-span-gap-ablation/study.json)固定：旧384题的256训练/128校准角色、FP32/INT8两种精度、原全窗口/新本窗口两种方法、原五特征维度、L2=1、Newton/Armijo设置、梯度门槛1e-8和原阈值网格。每个组合只拟合一次。报告同时比较共同阈值0.7，以及各自从同一网格中选出的最低合格阈值。

所有特征和EM标签先从已固定raw logits重算，与原存档核对；再使用已核验的原矩阵，仅替换第三列。其它四列不重新生成浮点输入，避免将平台尾数差异混入此次单因素消融。本机raw/存档最大差异实测为0。训练矩阵为`[256,5]`、标签为`[256]`；校准矩阵为`[128,5]`。scaler仅用训练矩阵拟合。

本次没有调用基础模型，没有下载权重，没有消费独立的 `qa-risk-v2/evaluation-int8` 128题。代码读取的旧 `qa-specialist-v1/evaluation-*` 文件已在原排序研究中明确降为开发数据，是本次训练/校准来源的一部分。不能把目录名字中的evaluation误认为这次又评估了新集合。

学习参数只存在于内存，不写入Git或交付包；公开非参数loss/gradient轨迹、矩阵、标签、校准分数、完整阈值曲线和参数摘要。训练从原存档输入重建的跨平台边界没有扩大。

| FP32 全窗口 | 37 / 31 | 83.78% | 35/64 = 54.69% | 2/64 = 3.13% | 无合格阈值 |

FP32两臂均8次迭代、目标177.445678→79.579337、最终最大梯度约1.46e-14；INT8两臂均7次迭代、目标177.445678→86.737843、最终最大梯度约4.46e-10。四次拟合均成功；FP32校准仍失败。训练目标下降不等于校准门槛通过。

| 数据角色（每个精度） | 单窗口 | 双窗口 | 第三特征改变的样本 |

两个双窗口训练样本的全局最佳不同答案也都在选中窗口0，所以局部限制没有排除真正的竞争者：

- `5725f2c838643c19005aceef`：选中“2,500”，两精度的最佳不同答案都是同窗“up to 2,500”。

## Interpretation / 应如何解释

1. **实现验证成立：** 两窗合成反例能区分两个定义，索引映射、非目标特征、重复答案排除、无局部alternative及无效其它窗口都经过检查。
2. **本次没有效果提升：** 数据未使被修改的数值发生变化，比较缺少实际干预差异。相同结果是可预期的，不能写成“新特征无损”“等价性验证通过”或“优化成功”。
3. **揭示了评测覆盖缺口：** 当前开发集对跨窗竞争机制的检验很弱；校准集甚至没有多窗口问题。这个发现比强行把相同指标解释为改进更可靠。
4. **保持默认方案：** 没有证据支持切换特征；局部方案还会丢掉跨窗口竞争信息。此次不追加挑样本、模型、solver或阈值搜索。
5. **下一阶段需要另立协议：** 如果未来研究长文多窗口，需事先定义真实使用分布和跨窗覆盖条件，再采集/划分材料。本次合成反例只能验机制，不能替代业务质量评估。

## Reproduce / 复跑

在仓库或解压源码根目录，使用NumPy2.2.6和记录的Python3.12本地环境；每次新建目录，失败保留：

```bash
python -m experiments.my_span_gap_ablation --output-dir runs/my-span-gap-reproduction
python -m experiments.verify_span_gap_ablation \
  --root runs/my-span-gap-reproduction --output runs/my-span-gap-audit.json
```

第一个命令重新拟合四个小头，属于公开开发数据复现，不是新确认；第二个只检查已存记录及特征/指标算术，不拟合。CI只对这次新实验执行后者；其它已有CI步骤仍核验原项目历史证据。
